# ハイ＆ローの日次履歴

## 利用者向けの動作

- 日本時間の0:00〜24:00に記録されたハイローの残高増減を、翌日午前1時に1人1件へまとめる。
- 取引履歴は日次収支だけを表示する。賭け金・配当の個別記録、表示切り替え、暫定収支は表示しない。当日分は翌日午前1時の集計後に表示する。
- 表示内容は対象日・残高増減・賭け金合計・受取合計。LEVELIA Gamesの結果はDMで送らない。
- 残高増減は「受取合計 − 賭け金合計」。収支0でもその日に増減があれば履歴を作る。ハイローの増減がない日は作らない。
- 通常の取引履歴の収入・支出フィルターでは日次の差引収支で判定する。収支0は「すべて」にだけ表示する。日次行は対象日の末尾時刻に置き、他の取引と日付順に並べる。
- 日をまたいで遊んだ場合は、賭け金と配当をそれぞれ実際に残高へ記録した日に含める。前日に開始したゲームの自動精算だけがある日も対象。ゲームの開始日へ配当を遡及させない。

表示例:

```text
2026/10/03 ハイ＆ロー収支
残高増減：+3,200 LIA
賭け金合計：20,000 LIA
受取合計：23,200 LIA
```

## 記録・障害時の扱い

- 集計元は共有DBの実残高用`levelia_game_high_low_ledger`。UTCの記録時刻を日本時間の日付に換算し、開始時刻以上・終了時刻未満で集計する。`wager_debit`が賭け金、`payout_credit`と`auto_payout_credit`が受取。合計収支は台帳の`supply_delta`と照合する。
- 仮想用台帳や送金・給与等は集計しない。`accounts`、`actions`、ゲーム台帳の既存記録は変更・削除しない。日次行は表示用であり、`actions`への追加や残高への再適用は行わない。
- `levelia_game_high_low_daily_reports`へ対象日・本人・合計額を保存する。対象日と本人の組み合わせは一意。既存のDM状態列は過去データとの互換性のため残す。
- `levelia_game_high_low_daily_state`の処理日をロックし、日次記録と次の処理日を同じトランザクションで確定する。並列実行や再起動で同じ日の履歴を重複作成しない。
- 通常は01:00に実行し、5分ごととBot起動時にも未処理分を確認する。1回につき最大31日。停止中の未処理日は順次追いつく。
- 各日の集計時点でコミット済みの台帳を確定値として保存する。午前1時より後の入金は当日の分となり、前日分を再計算・再送しない。
- 過去バージョンが残した`pending`または`sending`のDM状態は、起動時・定期処理時に`skipped`へ変更し、送信しない。
- 日次テーブル未作成でも通常の履歴は表示できるが、ハイローの個別履歴へは戻さない。導入時は先にマイグレーションを完了する。

## 導入

1. 既存の実残高用ハイロー台帳がある共有DBで、`src/sql/20261003_high_low_daily_reports.sql`を実行する。繰り返し実行しても既存の処理日・通知開始日を上書きしない。
2. KARUMAを更新する。Activity側の接続確認やゲーム処理の変更は不要。
3. 初回は過去の台帳から日次履歴を補完する。過去の日を含め、結果DMは送信しない。
4. 本番反映後は日付境界と日次履歴を照合する。

リリース補助コマンド（既存のRailway本番`karuma-bot`内で実行する）:

- `node scripts/release-high-low-daily.cjs check`: 台帳の整合性、日次テーブル・状態を読み取り確認。
- `node scripts/release-high-low-daily.cjs migrate`: 日次テーブル・初期処理日だけを追加。口座・元の台帳は変更しない。
- `node scripts/release-high-low-daily.cjs verify`: ローカルビルドと本番ファイルの一致、過去分の集計漏れ・金額差分、実際の履歴生成と切り替えボタンがないことを読み取り検証。Discordへ試験メッセージは送らない。

以前の利用単位案の`levelia_game_high_low_history_sessions` / `levelia_game_high_low_history_actions`は参照しない。もしローカル等に残っていても、本マイグレーションでは削除しない。

## 検証

- `npm run check`、`npm test`。
- DB統合テストは`TEST_HIGH_LOW_DAILY_MYSQL_URL`に専用のローカルMySQLを指定する。ホストはlocalhost/127.0.0.1/::1、DB名は`levelia_*test`に限る。
- そのDBのテスト用台帳・口座・履歴・日次テーブルを削除して再作成するため、本番や他のテストと共有しない。
- 01:00直前・直後、日またぎ、差引0、仮想データ除外、並列集計、集計失敗のロールバック、DM無効化、既存履歴の非表示、金銭データの不変性を検証する。
