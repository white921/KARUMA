# サービスの配置

機能ごとに処理とパネルを同じフォルダーに置く。コマンドの入口は
`src/command`、イベントの振り分けは `src/handler`、設定値は `src/constant`
で管理する。

| フォルダー | 責務 |
| --- | --- |
| `account` | 口座の開設・連携、表示名変更、再参加時の口座確認 |
| `currency` | 残高、送金、付与・剥奪、給与、取引履歴、銀行パネル |
| `vc` | 共通VC操作、移動、狭間、独房 |
| `hotel` | ホテルVC、ホテルパネル、ホテル無料券 |
| `game` | 遊戯VC、利用権、遊戯パネル、遊戯無料券 |
| `market` | 市場の購入・ガチャ・割引券・招待ポイント、創作者紋章、スーパーチャット、売上集計 |
| `inventory` | 共通アイテム所持数、各種チケットの所持一覧 |
| `casino` | 賭博パネル、ルーレットの受付・精算・ルール |
| `omikuji` | おみくじ抽選とパネル |
| `diary` | 日記の作成・管理とパネル |
| `evaluation` | 面接、名前確認、シフト通知、評価シートとアーカイブ |
| `member` | ロール変更、まどろみ通知、ブースト報酬、日次通知 |
| `system` | DB接続、Botの健全性監視、再デプロイと操作パネル |
| `panel` | 設置先チャンネルに応じた各機能のパネル設置の振り分け |

## 追加・変更時のルール

- まず既存の機能フォルダーに置けるか確認する。機能固有のパネルやチケット処理も同じ場所に置く。
- `panel` は設置の振り分け専用。銀行パネルは `currency`、ホテルパネルは `hotel` に置く。
- 共通の所持数操作は `inventory` に置き、ホテル・遊戯などの利用条件は各機能で扱う。
- importは対象ファイルを直接指定する。一括再export用の `index.ts` は追加しない。
- 固定の料金表・権限一覧・メッセージ・タイムアウト・パネル識別子は `src/constant` の機能別ファイルに置く。クラス内の固定値も同様に扱う。
- `interface`・名前付きの `type` は `src/type` の機能別ファイルに置き、`import type` で参照する。DB取得結果の型や、定数から導出する型もここに置く。
- 関数内の計算結果や一時変数、Map・接続プール・監視状態など実行中に更新する状態は、使用するサービスで管理する。
- ファイルを移動したら、呼び出し元のimportと `test` のビルド成果物・ソース参照を合わせて更新する。
- フォルダー分けは実行時の機能の有効・無効を表さない。機能の状態は既存の呼び出し元・設定に従う。

この整理は配置と参照先のみを変更している。機能間の依存関係は引き続き存在するため、
フォルダー単位で独立してデプロイできる構成ではない。
